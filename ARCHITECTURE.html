Architecture & Codebase Analysis: WEBBLOG

This document contains a comprehensive analysis of the WEBBLOG Python Flask web application codebase, including application architecture, execution lifecycles, database models, blueprint routes, templates, and styling.

1. Overall Application Architecture

WEBBLOG is a Python Flask web application designed to record and present trading strategies, trade journals, P&L analytics, and educational notes (focused on E-Micro Futures trading / MNQ).

The project is structured using the Flask Application Factory Pattern combined with Flask Blueprints for modularity.

2. Startup & Execution Program Flow

User -> run.py [-port PORT] [-debug] [-fdt]
      -> argparse parses CLI arguments
      -> create_app(config_class=Config) in flaskblog/__init__.py
      -> Init db, bcrypt, login_manager, mail
      -> Register blueprints: users, posts, main, errors
      -> Returns app instance
      -> app.run(port=args.port)
  1. Invocation: Executing run.py parses command line arguments via argparse:
    • -port: Custom port (defaults to 5000).
    • -debug: Activates Flask Debugger.
    • -fdt: Enables Flask-DebugToolbar.
    • -fdt_redirect: Controls DebugToolbar redirect intercepts (DEBUG_TB_INTERCEPT_REDIRECTS).
  2. App Instantiation: run.py calls create_app() from flaskblog/__init__.py.
  3. Extension Binding: Loads Config settings from flaskblog/config.py and initializes extensions (db, bcrypt, login_manager, mail).
  4. Blueprint Registration: Registers blueprinted route modules (users, posts, main, errors).

3. Database Schema & Data Models

Defined in flaskblog/models.py:

User Model

  • id (Integer, Primary Key)
  • username (String(20), Unique, Not Null)
  • email (String(120), Unique, Not Null)
  • image_file (String(20), Default: 'default.jpg')
  • password (String(60), Hashed with Bcrypt)
  • posts (db.relationship('Post', backref='author', lazy=True))
  • Methods: get_reset_token() (uses itsdangerous TimedJSONWebSignatureSerializer), verify_reset_token(token).

Post Model

  • id (Integer, Primary Key)
  • title (String(100), Not Null)
  • date_posted (DateTime, Default: utcnow)
  • content (Text, Not Null)
  • user_id (Integer, Foreign Key user.id, Not Null)
  • Custom Teaser Metadata Fields:
    • teaser_title, teaser_details, teaser_caption, teaser_img, teaser_content, teaser_wkid

4. User Authentication & Authorization Flow

Handled in flaskblog/users/routes.py, flaskblog/users/forms.py, and flaskblog/users/utils.py:

  • Landing Route (/): Serves frontend.html. If user is authenticated, redirects straight to /intro.
  • Guest User Mode: Special check in index() route allowing "GuestUser" fast pass to /intro.
  • Register (/register): Hashes password via bcrypt.generate_password_hash() and stores user.
  • Account Updates (/account): @login_required. Allows updating username, email, and uploading profile pictures. save_picture() generates a random hex filename, resizes the image to 125x125 using Pillow (PIL.Image), and stores it in static/profile_pics/.
  • Password Reset (/reset_password & /reset_password/<token>): Generates time-sensitive token, emails recipient via Flask-Mail (send_reset_email()), and verifies token before updating the password.

5. Content & Post Management Flow

Handled in flaskblog/posts/routes.py and flaskblog/posts/forms.py:

Endpoint Method Guard Description
/post/new GET, POST @login_required Creates a new post with teaser metadata fields.
/post/<post_id> GET Public Displays post details. Checks teaser_wkid to pass weekly variable to template.
/embed_viewer/<weekly_id> GET Public Displays embedded weekly trade viewer template (embed_viewer.html).
/detach_viewer/<weekly_id> GET Public Displays standalone/detached weekly trade viewer template (detach_viewer.html).
/post/<post_id>/update GET, POST @login_required Updates post; enforces author check post.author == current_user (returns 403 if mismatch).
/post/<post_id>/delete POST @login_required Deletes post; enforces author check.

6. Main Navigation & Page Routing

Handled in flaskblog/main/routes.py:

  • All main views require authentication (current_user.is_authenticated). Unauthenticated visitors are redirected to users.index (/).
  • /intro: High-level E-Micro Futures trading intro (intro.html), contract specs, schedule, strategy notes, and poem ("Shattered Innocence").
  • /methods: Trading methodology notes and study documentation (methods.html).
  • /trades: Paginated list of blog/trade posts (4 per page) using SQLAlchemy .paginate().
  • /pnl: Profit & loss tracking metrics and visualizations (pnl.html).
  • /about: System info, app root path, and instance path details (about.html).

  ├── account.html      (Extends layout.html -> {% block content %})

  • Navbar: Bootstrap 4 navigation header dynamically rendering nav links based on current_user state and guest vs member role.
  • Flashed Messages: Uses get_flashed_messages(with_categories=true) rendered inside dynamic Bootstrap .alert containers.

  • Modal Image Viewer: Global #myModal overlay controlled by static/js/modalpics.js for enlarging inline trade chart screenshots.

9. Proposed P&L Module Specification (Static Chart Caching)

Technical Design Overview

The P&L module (/pnl route) is designed to display daily, weekly, and monthly performance charts using a server-side static chart caching strategy:

  • Target Static Storage:
    • flaskblog/static/daily_pnl/
    • flaskblog/static/weekly_pnl/
    • flaskblog/static/monthly_pnl/

UI & Navigation Header

  • Timeframe Selector: Dropdown menu offering { Daily | Weekly | Monthly }.
  • Dynamic Inputs:
    • Daily: Single date picker (<input type="date">).
    • Weekly: Week picker or Monday start-date (<input type="week">).
    • Monthly: Start date picker (<input type="date">), automatically calculating metrics up to the current date (datetime.utcnow()).

Caching Execution Lifecycle

  1. User submits timeframe & date parameters to /pnl.
  2. Flask constructs the expected target chart filename (e.g., daily_2026-07-28.png).
  3. Flask checks os.path.exists(...):
    • Cache Hit: If file exists, Flask skips DB queries and chart rendering; serves url_for('static', filename='daily_pnl/daily_2026-07-28.png').
    • Cache Miss: If file does not exist, Flask queries trade data, computes statistics, generates the .png plot (e.g. via Matplotlib), saves it to disk, and serves the static image.
